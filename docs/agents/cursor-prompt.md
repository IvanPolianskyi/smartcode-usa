## 0. Контекст: що це за продукт і що ти робиш

SmartCode Academy — LMS на Next.js 16 (App Router, Turbopack, JS не TS), що продає
самостійні курси програмування за підпискою через Paddle. MongoDB, JWT-cookie auth.
Мова платформи — **тільки англійська** (`src/i18n/routing.js`: `locales: ['en']`).

Три курси:

| Курс | courseId | Уроків | Де контент |
|---|---|---|---|
| Python Developer: Zero to Junior | `python-developer-zero-to-junior` | 84 | `src/lib/lessonContent/en/` |
| Roblox Studio | `roblox-studio` | 92 | `src/lib/robloxLessonContent/en/` |
| AI at Work | `ai-at-work` | 28 | `src/lib/aiAtWorkLessonContent/en/` |

Проєкт готується до реального продажу. Це змінює планку: контент, за який людина
платить щомісяця, не має права містити зламану практику, квіз без правильної
відповіді або урок-заглушку. **Твоя мета — довести навчальний контент до рівня,
за який не соромно брати гроші.**

Ти працюєш **тільки з даними курсів**. Ти не чіпаєш React-компоненти, CSS, бандл,
роутинг, білінг і API — це зона іншого агента або власника.

### 1.3 Приклад «еталонного» уроку

Прочитай **цілком** три файли — це твій зразок форми й тону:

- `src/lib/lessonContent/en/lesson-02-1.js` — повний Python-урок (умовні конструкції).
- `src/lib/robloxLessonContent/en/module01-lessons.js` — Roblox, інша структура (модуль = один файл із багатьма уроками).
- `src/lib/aiAtWorkLessonContent/en/` (будь-який модуль) — найновіший курс.

Форма Python-уроку (ключі верхнього рівня):

```
lessonId, moduleId, order, title,
learningObjectives[], prerequisites[], videoUrl,
theory: { sections: [{ title, content }] },
codeExamples[], commonMistakes[], summary,
practiceTask: { title, description, problemStatement, outputFormat,
                examples: [{ input, output, explanation }],
                solution, hints[], difficulty },
quiz: { questions: [{ type, question, options[], correctAnswer, explanation }],
        timeLimit, passingScore }
```

`correctAnswer` — **індекс** у масиві `options`, не текст.

### 1.4 Як контент валідується в рантаймі

| Файл | Що звідти зрозуміти |
|---|---|
| `src/lib/practiceValidation.js` | `checkPracticeOutputs` — як порівнюється вивід студента з очікуваним. Нормалізує регістр, пробіли, невидимі символи. Це визначає, наскільки «строгий» твій `outputFormat`. |
| `src/lib/parsePracticeStdin.js` | Як `input` із `examples` перетворюється на stdin. Формат `Label: value` розпарситься в саме `value` — важливо, коли пишеш приклади. |
| `src/lib/pythonCodeGuard.js` | Які конструкції Python заблоковані в браузерному ранері. Твої `solution` не мають їх використовувати. |
| `src/lib/quizValidation.js` | Серверна перевірка квізу (**читати, не редагувати** — файл належить іншому агенту). |
| `scripts/verify_python_solutions.mjs` | Автоперевірка: запускає кожен `practiceTask.solution` реальним Python і звіряє з `examples[].output`. |

### C1. Інвентаризація контенту й скрипт аудиту (обов'язково)

Створи `scripts/audit-course-content.mjs` — читає всі три курси й друкує звіт.

Що має перевіряти по кожному уроку:

1. Урок з curriculum має контент-файл, і навпаки (сироти в обидві сторони).
2. `lessonId` у файлі збігається з ключем у curriculum; `moduleId` існує; `order` унікальний у межах модуля.
3. Наявність і непорожність: `title`, `learningObjectives`, `theory.sections`, `summary`, `practiceTask`, `quiz`.
4. `theory.sections` — жодної секції з порожнім або коротшим за 200 символів `content`.
5. `quiz.questions` — не менше 3 питань; кожне має `type` з `QUIZ_QUESTION_TYPES`, `question`, `options` (≥2 для multiple_choice, рівно 2 для true_false), `correctAnswer` — валідний індекс, `explanation` непорожній.
6. `practiceTask` — є `problemStatement`, `examples` (≥2), `solution`, `hints` (≥2).
7. Плейсхолдери: пошук `TODO`, `FIXME`, `Lorem`, `coming soon`, `TBD`, `XXX`, порожні рядки-заглушки.
8. Кирилиця в англійському контенті (regex `[Ѐ-ӿ]`) — зараз 0, це не має зламатися.

Вивід: таблиця по курсах + список проблем у форматі `файл — lessonId — проблема`,
плюс підсумок «N уроків, M проблем, з них K блокуючих». Exit code 1, якщо є блокуючі.

**Критерій приймання:** `node scripts/audit-course-content.mjs` запускається, звіт
збережений у `docs/agents/reports/content-inventory.md`, у status-файлі — підсумкові числа.

### C2. Автоматичний тест цілісності контенту (обов'язково)

Створи `src/lib/courseContent.test.mjs` у стилі існуючих тестів (подивись
`src/lib/paddle.test.mjs` і `src/lib/entitlements.test.mjs` — `node:test`, `node:assert/strict`,
без жодних фреймворків, коментар угорі з поясненням, що саме ламається без цього тесту).

Тест має падати, якщо хтось у майбутньому:

- додасть урок у curriculum без контенту;
- зробить `correctAnswer` поза межами `options`;
- залишить квіз без `explanation`;
- зламає граф `prerequisites` (посилання на неіснуючий урок або цикл);
- продублює `order` у межах модуля;
- залишить плейсхолдер у продакшн-контенті.

Це не дублювання C1: скрипт — для людини й разового звіту, тест — для CI та захисту
від регресій. Тест має бути **швидким** (без запуску Python, без мережі, без MongoDB).

**Критерій приймання:** `node --test "src/**/*.test.mjs"` зелений і містить нові
тести. Якщо тест на старті червоний — це знахідка: спочатку виправ дані, потім
залиш тест зеленим. **Не послаблюй тест, щоб він проходив.**

### C3. Якість квізів (обов'язково, батчами по модулях)

513 питань лише в Python. Проходь **модуль за модулем**, комітячи кожен модуль окремо.
Пріоритет: Python модулі 00→05 (там початківці і найбільший відтік), далі Roblox 1→3,
далі AI at Work, далі решта.

Критерії «доброго» питання:

- Перевіряє **розуміння**, а не пам'ять про формулювання з тексту уроку.
- Рівно одна беззаперечно правильна відповідь.
- Дистрактори правдоподібні: типова помилка новачка, а не абсурд. Викинь варіанти
  на кшталт «Python was invented by aliens».
- Немає «All of the above» / «None of the above» (з `correctAnswer` як індексом це
  ще й крихко при перестановці).
- Довжина правильної відповіді не виділяється серед інших (класичний leak).
- `explanation` **навчає**: пояснює не лише чому правильна правильна, а й чому
  найспокусливіший дистрактор — ні.
- Мікс типів: не всі 6 питань `multiple_choice`. Використовуй `code_reading`
  («що надрукує цей код») і `logic`.
- Питання не дублюють одне одного в межах уроку.

Обмеження: `type` бери **тільки** з `QUIZ_QUESTION_TYPES`, форму об'єкта не змінюй,
кількість питань в уроці не зменшуй.

**Критерій приймання:** у звіті `docs/agents/reports/content-quiz-audit.md` —
таблиця «модуль → питань переглянуто → переписано → залишено» і 5–10 прикладів
«було/стало» з поясненням, чому нове краще.

### C4. Практика: розв'язки, приклади, підказки (обов'язково)

Зараз 114 розв'язків проходять `scripts/verify_python_solutions.mjs`. Це означає
«solution дає очікуваний вивід», але не означає «задача добра».

Що зробити:

1. **Не зламати наявне.** Після кожної правки практики — прогін
   `node scripts/verify_python_solutions.mjs`, має лишатись `Failed: 0`.
2. **Edge cases.** У кожній практиці мінімум 3 `examples`: типовий випадок,
   граничний (0, порожній ввід, від'ємне, межа умови), і нетиповий. Зараз
   у частини уроків їх 2 — додай третій і **обов'язково** переконайся, що
   `solution` дає рівно той вивід (перезапусти верифікатор).
3. **`hints` мають вести, а не спойлити.** Правило: hint 1 — за що вхопитись,
   hint 2 — який інструмент мови застосувати, hint 3 (якщо є) — структура розв'язку
   словами. Жодного готового коду в підказках.
4. **`problemStatement` має бути однозначним.** Формат вводу і виводу описані так,
   щоб студент не гадав про пробіли, регістр і розділові знаки. Звіряй із тим, як
   `parsePracticeStdin.js` реально парсить `input` (`Label: value` → `value`).
5. **`difficulty` чесний** і зростає по курсу монотонно в межах модуля.
6. Розшир `scripts/verify_python_solutions.mjs`: хай перевіряє **всі** `examples`
   кожної задачі, а не лише перший, і друкує урок+індекс прикладу при падінні.

**Критерій приймання:** верифікатор зелений; у звіті — скільки практик отримало
третій приклад, скільки підказок переписано.

### C5. Тести для `practiceValidation.js`

Створи `src/lib/practiceValidation.test.mjs`. Це чиста функція, що вирішує, чи
зарахувати студенту практику, — зараз вона **без жодного тесту**, а помилка тут

Покрий: різні переноси рядків (`\r\n` vs `\n`), хвостові пробіли, різний регістр,
невидимі символи (`​`), зайві порожні рядки в кінці, порядок рядків, часткові
збіги, порожній вивід, вивід із зайвим текстом навколо правильного.

**Критерій приймання:** тести зелені; якщо знайшов реальний баг у нормалізації —
виправ у `practiceValidation.js` (це твій файл) і опиши в звіті.

### C7. Педагогічна якість теорії (найбільша задача — батчами)

Проходь модуль за модулем. Для кожного уроку теорія має мати:

1. **Гачок на початку** — навіщо це, у якій реальній ситуації знадобиться. Не «Lists are a data type», а конкретна задача, яку без цього не вирішити.
2. **Поступ від простого до складного**, без стрибків через нез'ясовані поняття.
3. **Приклад коду з розбором**, а не код без коментаря.
4. **`commonMistakes`** — реальні помилки новачків із цієї конкретної теми, з правильним варіантом поруч.
5. **`summary`** — 3–5 пунктів, які можна перечитати перед квізом.
6. Тон: до дорослого учня (Python, AI at Work) або підлітка (Roblox) — але ніколи не поблажливий.

Обмеження на формат: контент рендериться через власний markdown-парсер
(`src/lib/markdownToHtml.js` — прочитай, **не редагуй**). Підтримуються:
` ```code``` `, `` `inline` ``, `**bold**`, `*italic*`, `[link](url)`, списки, `→`.
**Не використовуй** таблиці, HTML-теги, вкладені блоки чи інші markdown-фічі —
парсер їх не обробляє, і на сторінці буде сміття. Після правки складного уроку
відкрий його в dev-сервері на `:3001` і подивись очима.

## 5. Тестування — окремо і обов'язково

Це не «якщо лишиться час». Контент без тестів деградує на наступному ж рефакторингу.

**Після кожної задачі:**

```bash
node --test "src/**/*.test.mjs"
```

```bash
node scripts/verify_python_solutions.mjs
```

**Перед кожним комітом:**

```bash
npm run build
```

**Правила:**

1. Тестів має ставати **більше**, ніж було (49 на старті). Менше — регресія.
2. Жодного `skip`, `only`, закоментованого тесту чи послабленого асерту заради зеленого прогону.
3. Новий тест спершу має **впасти** на реальному дефекті — тільки так ти знаєш, що він щось ловить. Опиши в звіті, на чому саме він упав.
4. Кожен новий тестовий файл починається коментарем: що зламається в продукті, якщо цей тест прибрати. Дивись `src/lib/paddle.test.mjs` як зразок такого коментаря.
5. Якщо `scripts/verify_python_solutions.mjs` упав після твоєї правки — **не міняй `examples[].output` під вивід зламаного розв'язку**. Виправляй розв'язок або задачу.
6. Якщо після падіння верифікатора в корені лишились `tmp_lesson-*.js` — видали їх, у коміт вони потрапити не мають.

## 6. Формат звіту

Веди `docs/agents/status/cursor.md` і оновлюй **після кожної задачі**, не наприкінці.
Формат — у `docs/agents/README.md` §5.

Обов'язково:

- Числа до/після для кожної задачі (не «покращив квізи», а «модуль 02: 34 питання
  переглянуто, 11 переписано, 3 дистрактори-абсурди прибрано»).
- Розділ `## Handoff` — усе, що знайшов у чужих або заморожених файлах: файл:рядок,
  опис, пропозиція, ризик. Особливо якщо це стосується `quizValidation.js`,
  `markdownToHtml.js`, `RobloxLessonPage.js` або API прогресу.
- Розділ `## Заблоковано` — де тобі бракує рішення власника.

Наприкінці сесії додай `## Підсумок` на 10–15 рядків: що змінилось у продукті
з точки зору студента, і що лишилось найпріоритетнішим.
